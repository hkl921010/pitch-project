# Pitch 项目体系方案（原型配套文档）

> 本文档随原型逐项更新。原型位置：`/Users/huangkelin/lighthouse/pitch-project`，运行 `pnpm dev` 后访问 `http://localhost:3100`。
> 本方案替代 `pitch-tree/pitch-project/specs/project/project-optimization-proposal.md` 的方向。

## 0. 问题与方向

**现状问题**

- 用户使用频率低：创建项目后没有“下一次回来”的理由——没有数据反馈、没有动态被看到、没有周期性节点。
- 创建门槛高：项目档案是一次性填完的长表单，像“投递 BP”，而不是“经营一个主页”。
- 展示弱：项目页只有静态信息，看不出“谁在关注、谁背书、最近在做什么”。
- 合作流程断：查看联系方式 / 发起连接 / 心愿单是三套互不相通的入口，发出之后没有状态，也没有站内对话承接。

**方向（参考 Peerlist / Contra / Cosign）**

把项目从“投递档案”重做为：**创始人公开主页 + 统一意向 + 站内对话 + 背书与路演节律**。

```
快速创建 → 公开项目页 → 发现页 / 需求 / 榜单 / 路演 / 活动 / 报道
       → 关注 · 背书 · 建议 · 意向 → 站内对话 → 申请 Pitch 撮合
       → 工作台数据与周报 → 发布动态 → 回到发现
```

| 参考 | 借鉴点 |
| --- | --- |
| Peerlist | 个人主页即作品集、开放状态（Open to）、项目发布节律、按周榜单 |
| Contra | 无佣金的直接连接、意向/询价统一入口、主页上的服务与可用状态 |
| Cosign | 署名背书、按维度计数、正向信号、“被谁背书”比“被多少人看过”更可信 |

## 1. 全局约定

- **演示身份切换器**：右上角虚线按钮，可切换 创始人林川 / 投资人周敏 / 人才陈一 / 合作方王岚 / 运营阿珂 / 新用户张三 / 游客。正式产品不存在。
- **数据**：全部为本地假数据，操作写入 localStorage（`pitch-proto-v1`），页面间真实联动；切换器里可“重置演示数据”。
- **原型时间**：固定为 2026-10-21 18:00（北京时间），便于“随机排序期”“正在直播”等状态稳定演示。
- **视觉**：Untitled UI 风格（Inter / PingFang SC、灰阶、1px 灰边框、轻阴影、8–12px 圆角、紫色聚焦环），品牌色沿用 Pitch Web：主色 zinc-900、辅色亮黄 `hsl(60 100% 58%)`、点缀紫 `hsl(259 52% 48%)`。组件库见 `/ui`。
- **状态规范**：每个业务组件都要有加载（骨架屏）、空状态（图标 + 一句原因 + 一个下一步动作）、错误（就地红字或提示条）、禁用（灰色 + 说明为什么不可用）。

## 2. 已确定的业务规则

- **项目：先发后审。** 创建即有公开页 `/p/[slug]`；上发现页、上榜单、进月度路演时才审核。可见范围分“公开到发现”和“仅持链接可见”。
- **成员：** 项目方邀请，对方确认后，项目出现在双方个人主页上。
- **统一意向：**
  - 类型：投资 / 合作（渠道、流量、品牌、服务）/ 加入团队（可指向岗位）/ 帮忙（回应某条“正在寻找”）/ 其他。
  - 默认实名，可选匿名；项目方点“我也想聊”后双方身份揭晓。
  - 项目方可选“开始聊”或“暂不考虑”；选“暂不考虑”时，发起方只看到“暂未回应”。为了不泄露拒绝，发出 7 天内无论对方是否处理都显示“等待回应”，7 天后统一为“暂未回应”并可再试一次。
  - 发起方可撤回。
  - 浏览和关注免费；非会员每月 5 次意向，完成贡献任务每项 +1（每类每月计一次）；会员不限。回复意向不消耗次数。
- **对话：** 意向被接受后自动创建，支持文字和附件、一键互换联系方式；状态：进行中 / 已申请撮合 / Pitch 跟进中 / 已结束。
- **撮合：** 用户在对话中申请，或运营主动介入；只有这一步才生成 CRM 商机。阶段为跟进中 → 已约见 → 成交 / 未成交，每一步都同步到对话里（F17）。介入前运营看不到对话内容。
- **身份：** 用户自选，不做认证；以“被 N 位投资人背书”作为软认证。
- **背书：** 署名，按维度计数（如“出海渠道 · 12 人背书”）；只做正向信号，不做踩和差评。
- **个人主页：** 保留名片上的 projectInfo、一句话、亮点，作为“我在做的事”，下面展示关联项目。
- **心愿墙并入：** 个人需求 → 主页“正在寻找”；发现页新增“需求”Tab；“产品建议”单独保留为反馈入口（头像菜单 → 给 Pitch 提产品建议）。
- **月度路演：** 完成度达标可报名，运营选入围；开放后前几天随机排序；用户可投票和关注。

### F01 首次引导与首页

**规则**

- 新用户登录后进入 `/welcome`，四步：选身份 → 基本信息（名字、职位必填，机构、城市选填）→ 开放状态（按身份不同）→ 你的 3 个第一步。
- 身份自选、不认证，之后可在主页修改。“稍后再说”可随时跳出；未完成引导时首页顶部常驻“花 30 秒告诉我们你是谁”。
- 开放状态按身份采集：
  - 创始人：一句话“我在做什么、在找什么”。
  - 投资人：赛道（多选）、阶段（多选）、单笔金额 → 自动生成一句话，如“在看 天使 · 消费品牌 项目，单笔 100–300 万”。
  - 人才：开放的机会（合伙人 / 全职 / 兼职顾问）、擅长方向。
  - 合作方：资源类型（渠道 / 流量 / 品牌 / 服务）、具体说明。
- 填写开放状态视为完成“刷新开放状态”贡献任务，本月意向次数 +1（所以新用户首页显示“还可发 6 次”）。
- 每个身份 3 个第一步，完成与否全部由真实数据推导，做完自动打勾，全部完成后卡片消失：

| 身份 | 第一步 1 | 第一步 2 | 第一步 3 |
| --- | --- | --- | --- |
| 创始人 | 1 分钟创建项目 | 写下正在寻找 | 转发项目页给 3 个朋友 |
| 投资人 | 设置投资偏好 | 收藏 3 个项目到观察清单 | 开放一个答疑时段 |
| 人才 | 设置开放状态 | 关注 3 个项目 | 向在招项目表达意向 |
| 合作方 | 写下能提供的资源 | 回应一条合作需求 | 关注 3 个项目 |

**首页（按身份）**

- 顶部：问候、本月剩余意向次数（会员显示“不限次数”，点击进任务中心）。
- 待处理条：待回应意向、未读对话、项目成员邀请、待确认答疑；没有就不显示。
- 创始人：我的项目（7 天浏览与环比、关注、待回应意向、资料完成度与下一项）、可能帮得上你的人（投资偏好匹配赛道的投资人、有资源的合作方）。
- 投资人：观察清单有更新（自上次查看后的新动态）、符合偏好的项目（排除已收藏）。
- 人才：在招岗位，一键“我想加入”（意向弹层预选岗位）。
- 合作方：等你回应的合作需求，一键“我能帮上忙”。
- 运营：撮合申请、上墙审核、路演报名三个待办数。
- 右栏：正在发生（正在直播的活动、本月路演、下一场活动）、Pitch 报道。
- 游客：落地页（价值主张、1 分钟上线 / 统一意向 / 站内对话三点、最近活跃项目、正在发生）。

**全局空状态规范**

- 组成：圆形图标 + 一句“为什么是空的” + 一句“怎么让它不空” + 最多两个按钮。
- 文案不说“暂无数据”，要说清下一步，例如“还没有收到意向 · 完善‘正在寻找’，让对的人找到你”。
- 列表内的空状态用紧凑版（compact），整页空状态用标准版。
- 游客遇到需要身份的空状态，按钮统一为“登录”，点击弹登录框并说明原因。

### F02 发现页 `/discover`

**规则**

- 四个 Tab：项目 / 人 / 需求 / 榜单。Tab 与主要筛选写入 URL（`?tab=needs&kind=join`），可直接分享或从首页跳转。
- 项目 Tab 只展示“公开到发现 + 上墙审核通过”的项目；“仅持链接可见”和审核中的项目不出现。
  - 本人有未上墙的项目时，顶部提示当前状态（审核中 / 未通过原因 / 未申请）并给出入口。
  - 筛选：搜索、正在寻找（在融资 / 找合作 / 在招人）、赛道（带数量）、地区。
  - 排序：熟人关注优先（默认）/ 最近有动态 / 关注最多 / 最新创建。
- 人 Tab：按身份筛选，“只看开放中”开关；你认识的人排在前面。不展示运营和未完成引导的用户。
- 需求 Tab：汇总项目的“正在寻找”和个人主页需求（原心愿墙，带“来自心愿墙”标记），可按类型、来源筛选。
  - 每条需求直接给出对应动作：我想投资 / 我能合作 / 我想加入 / 我能帮上忙，点击打开意向弹层并预选类型。
  - 自己发布的显示“我发布的”；已对该项目有待回应意向的显示“等待回应”（同一项目同时只能有一条待回应意向）。
- 榜单 Tab：精选在前，卡片展示策展人、条目预览、关注数。

**熟人信号**

- “你认识的人” = 和你有过对话的人 + 你关注的人。
- 卡片底部显示“李牧、高远 你认识的人关注或背书过”；人卡片上还显示“被 N 位投资人背书”的软认证。

**状态**：切换筛选时显示骨架屏；无结果时空状态给“清空筛选”。

### F03 项目公开页 `/p/[slug]`

**规则**

- 先发后审：任何人拿到链接都能访问（包括“仅持链接可见”的项目）；只有发现页、榜单、路演才看审核状态。
- 访问计数：非成员访问计一次浏览，来源取链接上的 `?from=`（wechat / moments / poster / discover / demoday / article），没有则记“直接访问”，进入工作台流量来源。
- 投资人访问时，如果项目在TA的观察清单里，自动标记“已查看”，清单里的“新动态”提醒消失。

**分区（自上而下）**

1. 本人横条（仅成员可见）：资料完成度、可见范围与上墙状态、编辑资料、工作台。
2. 封面图集：大图 + 3 张缩略图，点开可左右浏览；没有图时成员看到“上传封面与产品图”。
3. 头部：Logo、名称、徽章（悬停看获得条件）、一句话、赛道与标签、地区、官网、关注数、熟人信号；关注、加入观察清单（仅投资人）、分享（复制带来源的链接）。
4. 正在寻找：每条需求带对应动作按钮，打开意向弹层并预选类型与需求。
5. 关于项目：在做什么 / 在卖什么 / 凭什么。
6. 团队：已确认成员；管理者还能看到“待TA确认”的邀请和“邀请成员”入口。
7. 在招岗位：类型（合伙人 / 全职 / 兼职顾问）、地点、说明，“我想加入”预选岗位。
8. 动态时间线：模板标签（上线 / 融资 / 招人 / 获奖 / 里程碑），成员可“发布动态”。
9. 背书：按维度汇总，点开看署名原文；非成员可写，成员不能给自己项目背书；可撤回自己的背书。
10. 建议区：分类 + 文本（≥10 字），默认仅项目方可见；项目方可公开、标记“有用”、回复。写建议的人能看到自己那条（标“仅你和项目方可见”）。
11. Pitch 报道、参与的活动（直播中 / 即将开始 / 已结束）。
12. 右栏：意向卡（见 F04）、关注 / 背书 / 浏览小计、相似项目（同赛道或同标签）。

**意向卡状态**：游客 → 点击弹登录；成员 → 显示待回应意向数与回复速度；已发意向 → “等待回应”+ 撤回；已接受 → “打开对话”；7 天未回应（含被“暂不考虑”）→ “暂未得到回应”，可再试；默认 → 四个类型按钮，项目正在寻找的类型高亮。

**回复速度标签**：近 30 天意向回复中位时长 ≤12 小时“通常半天内回复”、≤24 小时“通常 1 天内回复”、≤48 小时“通常 2 天内回复”、更慢“回复较慢”、无记录“暂无回复记录”。

**移动端**：意向卡改为底部固定条（关注 + 表达意向），位于底部导航上方。

### F04 统一意向

**规则**

- 一个入口代替“查看联系方式 / 发起连接 / 心愿墙留言”。入口：项目页意向卡、正在寻找的每条需求、在招岗位、发现页需求 Tab、首页按身份推荐、个人主页“正在寻找”。
- 类型：想投资 / 想合作（渠道、流量、品牌、服务）/ 想加入团队（可选具体岗位）/ 帮忙（回应某条需求时自动带上）/ 其他。入口带预选类型与需求、岗位。
- 来意 10–200 字，必填；按类型给 2 条模板，点一下填入。
- 匿名：开关旁实时预览“对方会看到”。匿名时只显示身份类型与偏好（如“一位早期投资人，关注 AI 应用 · 企业服务”），不显示姓名、机构、头像。
- 发送限制：
  - 非会员每月 5 次 + 贡献任务奖励（每类每月 +1），会员不限；回复不消耗。
  - 同一项目 7 天内只能有一条等待中的意向（提示“你已经对这个项目表达过意向”）。
  - 次数用完：弹层顶部警示条 + “去做任务”，发送按钮禁用；意向卡底部同样提示。
- 项目方处理（`/me/intents?tab=received`，工作台“意向”页复用同一组件）：
  - 实名意向：“开始聊” / “暂不考虑”。
  - 匿名意向：“我也想聊” / “暂不考虑”。点“我也想聊”双方身份同时揭晓并开启对话；“暂不考虑”则发起方身份永远不揭晓。
  - 接受即自动创建对话，第一条是发起方的来意，第二条是系统消息“X 接受了你的合作意向 / 点了我也想聊”，并跳转到对话。
- 发起方视角（不泄露拒绝）：
  - 7 天内：等待中与被暂不考虑一律显示“等待回应”（匿名为“匿名等待中”），可撤回。
  - 7 天后：一律显示“暂未回应”，可再试一次。
  - 已接受：“已开始对话”+ 打开对话。撤回：对方不再看到，次数不退回。
- 通知：收到意向通知项目方（匿名时标题为“一位匿名投资人对拾光茶事感兴趣”）；被接受通知发起方并链接到对话。

**页面**

- 意向弹层（全局，任何页面调起）：项目/人概要 + 回复速度 → 类型卡片 → 合作方向 / 岗位 → 来意 + 模板 → 匿名开关与预览 → 底部“本次消耗 1 次 · 本月剩余 N 次”。发送成功页给“继续浏览 / 查看我的意向”。
- `/me/intents`：我发出的 / 我收到的（待回应 / 已处理）/ 成员邀请；右上角本月次数卡（已用 / 上限、含任务奖励、“赚次数”）。

**状态**：游客点任何意向入口 → 登录弹窗；无内容 → 各 Tab 独立空状态（发出：去发现页；收到：完善正在寻找；邀请：说明邀请如何产生）。

**视角验证（F04）**：人才陈一匿名发合作意向 → 创始人林川收到“匿名人才”并点“我也想聊” → 对话创建、身份揭晓；投资人李牧的匿名意向被暂不考虑 → 李牧端仍显示“匿名等待中”并能撤回；陈一用完本月 6 次（基础 5 次 + 写建议奖励 1 次）后弹层出现额度用完提示。

### F05 收件箱与对话 `/inbox`

**规则**

- 对话只由“接受意向”产生，不能凭空私信任何人。第一屏固定展示“对话起点”卡片：谁、什么类型的意向、原始来意、关联项目、时间；匿名意向标“匿名发出 · 已揭晓”。
- 消息：文字（Enter 发送，Shift + Enter 换行）+ 附件（BP、产品手册等，展示文件名与大小）。第一次发言前给 3 条快捷开场白。
- 联系方式：
  - 默认谁都看不到对方的联系方式。任一方点“分享我的联系方式”，填写/确认微信、手机、邮箱（至少一项，同时保存到自己资料），对方立即可见。
  - 对方已分享时按钮变为“交换联系方式”；双方都分享 → 系统消息“双方已互换联系方式”，右栏标“已互换”。
- 撮合（只在这里生成 CRM 商机）：
  - 任一方在对话中申请：选择希望 Pitch 帮什么（线下会面、引荐跟投人、尽调资料、条款建议、渠道对接，可多选）+ 说明（≥10 字）。
  - 申请后对话状态“已申请撮合”，对方收到通知，运营收到待办；运营接手后变为“Pitch 跟进中”，跟进说明显示在对话顶部横条和右栏进度里。
  - 每段对话只能申请一次；运营也可以主动介入（F17）。
- 对话状态：进行中 / 已申请撮合 / Pitch 跟进中 / 已结束。撮合结案后，“Pitch 跟进中”显示为“撮合成交”或“撮合未成交”，右栏进度多出“已约见”和结果两步（F17）。
  - 结束：选择原因（已达成合作 / 已转到线下沟通 / 暂时不合适 / 其他），对方在对话里看到；结束后输入框替换为“重新开启”。
  - 重新开启：恢复到结束前的状态（有撮合则回到撮合状态）。
- 未读：最后一条消息不是自己发的、且晚于自己的已读时间即为未读；自己的操作产生的系统消息不算未读。打开对话即已读，同时把该对话相关通知标为已读。

**页面**

**状态**：无对话 → “还没有对话”+ 去看看谁在找人；筛选无结果 → 清空筛选；非对话成员访问 → “对话不存在或你无权查看”；游客 → 登录；运营打开有撮合的对话 → 只读视角，引导去撮合看板。

### F06 快速创建 + AI 预填 + 完善清单 `/p/[slug]/edit`

**规则**

**状态**：BP 空闲 / 读取中（进度条）/ 已提取（字段清单 + 换一份）/ 失败；表单未改 / 有修改 / 已保存；`?new=1` 新建成功横幅；游客 → 登录；项目不存在；非成员 →“只有项目成员可以编辑”。

### F07 项目工作台 `/dashboard/[slug]`

### F09 投资人观察清单 `/watchlist`

**规则**

- 只对投资人开放：入口在项目页“加入观察清单”和头像菜单。其他身份打开时说明“这是投资人工具”，引导他们用“关注”。
- 关注与观察清单的区别：
  - 关注是公开计数，任何人都可以用。
  - 观察清单完全私密。项目方在工作台只看到“X 位投资人把你加入了观察清单”，看不到是谁，也看不到备注。
- 私人备注：每个项目一条，最多 200 字，记录编辑时间。移出清单时如果有备注，需要二次确认（备注会一起删除）。
- 更新提醒（按项目设置）：
  - 所有动态（默认）。
  - 仅关键动态：上线、融资、获奖、里程碑。招人和自由发布不提醒。
  - 不提醒：只在清单里标“有新动态”。
  - 观察者收到的提醒是“观察清单里的 X 有新动态”，直达清单里对应的卡片（`/watchlist#w-项目ID`）。同一个人既关注又观察时，只按观察清单的设置提醒一次。
  - 项目成员不会收到自己项目的动态提醒。
- 已读：打开项目页或点“标为已读”会更新查看时间。“有新动态”指查看时间之后发布的动态，首页“观察清单有更新”和投资人周报都用同一个口径。
- 接触状态：没发过意向 → 表达投资意向；已发 → 等待回应 / 暂未回应；对方接受 → 对话中（直达对话）。

**页面**：
- 标题区：隐私说明，全部标为已读，发现更多项目。
- 三个数字：观察中、有新动态、已接触。
- 筛选：全部 / 有新动态 / 有备注，同步到 `?filter=`。
- 排序：新动态优先（默认），或最近加入。
- 每张卡片包含：
  - 项目基本信息，以及“在融 · 轮次”标签（来自项目“正在寻找”里的融资需求）。
  - 接触状态按钮。
  - 新动态（最多 3 条）和“标为已读”；没有新动态时显示最近一条。
  - 黄色便签样式的私人备注。

### F12 周报与通知 `/notifications`、`/digest`、`/digest/preview`

**规则**

- 三个出口，分工不同：
  - 站内通知中心：保留全部通知，是唯一完整的记录。
  - 服务号即时提醒：只推用户勾选的类型。默认推送需要对方等你回应的事：意向、对话、成员邀请、答疑预约。
  - 周报（服务号和邮件）：每周一 09:00 发送，统计上周一到周日。其余通知只汇总进周报，不单独打扰。
- 通知按类型分组：
  - 意向与对话：意向、对话、成员邀请、答疑预约。
  - 项目：建议、项目动态、月度路演。
  - 与我有关：背书、奖励。
  - 系统：审核结果、测试发送等。
- 是否推送到服务号，在通知产生的那一刻按当时的设置决定，并记录在通知上（通知中心显示“已推送到服务号”）。之后改设置不影响已有通知。
- 服务号：微信登录时默认关注。没关注或关掉推送时，即时提醒和周报都只在站内。
- 邮件：需要填写邮箱（校验格式），可以单独关闭。邮件底部有“调整频率”和“退订邮件周报”，退订需要确认，只影响邮件。
- 周报频率：
  - 每周一份（默认）。
  - 有待办时才发：创始人有待回应的意向、未处理的建议或未确认的成员；投资人有待确认的答疑或观察清单有新动态；其他人有待回应的意向或成员邀请。没有这些的那一周跳过。
  - 不接收：站内通知和服务号即时提醒照常。
- 三个版本，按身份和数据自动选择：
  - 创始人版（管理至少一个项目）：
    - 浏览、新增关注、新意向、观察清单人数，以及流量来源占比。
    - 等你回应的意向。匿名意向只显示画像。
    - 本周值得做的事，最多 4 条：回应意向、处理建议、成员确认、两周没发动态、路演投票或报名、补全资料。
    - 关注你赛道的投资人（已表达过意向的会标出）。
    - 近期活动。
  - 投资人版：
    - 观察清单的新动态，口径与观察清单的“有新动态”一致。
    - 符合偏好的项目：赛道或在融轮次符合开放状态，不含已在清单里的。
    - 答疑时段、本月路演入围项目和是否已投票。
    - 报道和活动。
  - 精选版（人才、合作方等）：等你回应的事、和身份相关的“正在寻找”、在招岗位（人才）、最受关注的项目、报道和活动。
- 周报里所有条目都能直接点进对应页面（工作台的 Tab、观察清单卡片、项目页、活动页等）。
- “发一份测试”：按当前数据立即发一份到服务号（没关注时发到邮箱），通知中心留一条系统通知，服务号里显示为“（测试）”周报。

**页面**：

  - 标签：全部 / 未读（计数）/ 四个分组（有未读时显示红点），同步到 `?tab=`。
  - 列表按今天 / 近 7 天 / 更早分组。每条显示类型图标、标题、摘要、时间、类型，以及是否已推送到服务号。
  - 点击后标为已读并跳到对应页面。未读的可以单独“标为已读”（桌面悬停出现，移动端常显）。可以全部标为已读。
  - 右侧：本周周报要点和预览入口，服务号推送的类型和修改入口。
- 提醒设置 `/digest`：
  - 接收渠道：服务号（未关注时弹二维码模拟关注）、邮箱（填写、修改、开关）。
  - 周报频率：三选一，下方实时说明下一期会不会发、发到哪里。

### F13 月度路演 `/demo-day`、`/demo-day/[id]`

**规则**

- 每月一期，是一场线上活动（活动页可以预约和观看），每期有主题。
- 报名：
  - 条件：项目资料完成度 ≥ 80%，可见范围为公开。不要求已上发现页。
  - 从项目工作台的“曝光”报名，写一句“路演想讲什么”（至少 10 个字）。
  - 每个项目每期只能报名一次，截止时间之后不再接受。
  - 报名信息只有项目方和运营能看到。路演页只显示“另有 N 个项目待评审”。
- 入围：运营随报随审，按进展、完成度和赛道多样性每期选 6 个左右。入围会获得“路演入围”徽章并收到通知；未入围也会收到通知，可以下期再报。
- 投票，和报名同时进行：
  - 每人每期 3 票。同一个项目只能投 1 票，路演夜结束前可以撤回改投。
  - 不能给自己参与的项目投票。
  - 本月第一次投票完成“投票”贡献任务，意向次数 +1。
  - 游客点投票先登录。
- 随机排序期：开放后的前几天（本期到 10/23 00:00），名单对每个人随机排序（同一个人当天顺序不变），不公布票数，避免先入围的项目占便宜、大家跟着票数投。之后按票数排序并公开票数和名次。
- 路演夜：每个项目 6 分钟展示加 4 分钟问答。结束时票数最高的前三名获得“月度路演前三”徽章，票数锁定。
- 战报：每期结束后生成，可以分享。内容包括在线观看人数、收到的意向、进入撮合的数量、总票数、前三名领奖台、完整排名、项目方的一句话、现场回顾、回放和报道。
- 路演卡片上的转化：关注项目，或表达意向（说明自动带上“在 Pitch 某月月度路演看到你们，”）。投资人默认选“想投资”。

**页面**：
- `/demo-day`：

### F16 答疑预约 `/office-hours`

**规则**

- 谁能开放时段：投资人和合作方，他们是被找的一方。所有登录用户都可以预约，自己的时段不能约。
- 开放时段：
  - 填主题（1–20 字），选未来 14 天里的日期、09:00–21:30 的开始时间。
  - 时长 20、30、45 或 60 分钟。
  - 方式：线上，或线下（在答疑人所在城市）。
  - 不能和自己未结束的时段重叠。
  - 同时开放中的时段最多 6 个。
- 预约：
  - 写清楚想聊什么（10–120 字）。不消耗意向次数。
  - 同一位答疑人同时只能有 1 个未结束的预约（待确认或已确认），结束或取消后才能再约。
- 确认：
  - 答疑人确认时必须填会议链接或会议号（线上），或见面地点（线下）。这些信息只发给预约人。
  - 婉拒可以写一句原因。时段重新开放。
- 取消：
  - 预约人可以取消待确认或已确认的预约。答疑人会收到通知，时段重新开放。
  - 答疑人可以删除没人约的时段，不通知任何人。
  - 答疑人取消已确认的答疑时，可以写原因，预约人会收到通知。
- 过期与结束：
  - 时段开始前没确认的预约、没人约的时段，都自动变成“已过期”。
  - 已确认的答疑过了结束时间，显示“已结束”。预约人可以“继续聊聊”，发意向时说明会自动带上“谢谢上次答疑（主题），”。
- 通知（类型“答疑预约”，默认即时推送）：
  - 答疑人收到：有人预约、预约人取消。
  - 预约人收到：已确认（附会议信息）、被婉拒（附原因）、答疑人取消。

**页面**：`/office-hours`，标签同步到 `?tab=`

- 找人答疑 `browse`：
  - 筛选：投资人 / 合作方，线上 / 线下。
  - 答疑人卡片按最近的可约时段排序。卡片显示头像、身份与机构、城市、背书数、可约时段数，以及关注的赛道或能提供的资源。最多列 3 个时段，可以直接预约。

### F17 运营撮合看板 `/ops`

**规则**

- 只有 Pitch 运营能打开。其他人看到“运营看板只对 Pitch 运营开放”，并被引导去收件箱申请撮合。
- 撮合就是 CRM 商机，全部挂在对话上。运营的每一步都同步给双方：
  - 对话里加一条系统消息。
  - 双方各收到一条通知（类型“对话”）。
  - 顶部横条和右栏进度会更新。
- 撮合有四个阶段：跟进中、已约见、成交、未成交。成交和未成交表示结案。
  - 接手、主动介入、更新进展时，都必须写一句说明（至少 6 个字），双方都能看到。
  - 每一步都记进“跟进记录”，带日期和操作人。
  - 同一段对话只能有一个运营接手，已结束的对话不能主动介入。
- 主动介入的对象：还没申请撮合、但出现以下任一信号的对话：
  - 投资意向；
  - 双方已互换联系方式；
  - 近 7 天超过 4 条消息。
- 高意向项目：
  - 范围是公开项目，按近 14 天的意向数（投资意向加权）、投资人观察数和 7 天浏览量排序，取前 8 个。
  - 如果有意向超过 2 天没回应，可以“提醒回应”。项目负责人会收到“N 条意向超过 2 天没回应”，链接到工作台的意向收件箱。同一项目一天只能提醒一次。
  - “收进榜单”只能用自己策展的项目榜单，必须写收录理由。项目没上发现页时不能收。收录后的通知规则同 F14。
- 上墙审核：
  - 通过后，项目出现在发现页。
  - 不通过时必须写原因，可以用预设：资料不完整、缺少可验证的进展、疑似重复、不是早期创业项目。项目方收到原因，改完可以重新申请。
  - 无论通过与否，公开页都不受影响（先发后审）。
- 路演审核：
  - 每期入围 6 个左右，审核时看到当前入围进度。
  - 如果已入围项目里有同赛道，会提示，方便保持赛道多样。
  - 入围后，项目方获得“路演入围”徽章。不入围时原因选填。

**页面**：`/ops`，标签同步到 `?tab=`
- 撮合 `match`（默认）：
  - 顶部四个数字：待接手、跟进中、已成交、可主动介入。
  - 待接手：等得最久的排前面。卡片显示双方、项目、意向类型、消息数、申请说明和等待天数。可以“接手”，或“查看对话”。
  - 跟进中：卡片显示阶段标签、最新进展、可展开的跟进记录。可以“更新进展”，在弹层里选阶段、写说明。
  - 可以主动介入：卡片只显示信号标签、消息数和最近一条消息的时间。介入前运营看不到对话内容，也没有“查看对话”，加入撮合后才能查看（与 F05 的运营只读视角一致）。
  - 已结案：显示结果和跟进记录。
- 高意向项目 `hot`：
  - 每行显示排名、项目、负责人。
  - 四个指标：14 天意向（含投资意向数）、投资人观察、7 天浏览（含环比）、撮合数。
  - 回应情况：有几条积压，以及平均回复时长。
  - 操作：提醒回应、收进榜单、看项目。
- 上墙与路演审核 `review`：
  - 两栏。左栏是上墙审核，右栏是本期路演报名。
  - 每张卡显示完成度进度条和还缺哪些项。路演报名卡还显示“路演想讲”。
  - 下方分别列出未通过的项目（附原因）和已入围的项目。
- 其他入口：
  - 首页“运营待办”的三个数字；
  - 头像菜单；
  - 撮合申请通知；
  - 收件箱的运营只读视角。

**状态**：
- 每个分区都有空状态：没有待接手、没有跟进中、暂时没有需要主动介入的对话、没有待审核项目、没有待评审报名。
- 本月路演还没开放 → 说明。
- 没有可用的项目榜单 → 新建榜单。
- 没写说明或原因 → 报错。
- 今天已提醒 → 按钮置灰。

### 4.6 原型之外、上线前要定的事

- 会员体系：意向次数按会员等级的具体档位，以及付费入口。
- 运营的 SLA：多久内接手撮合、审核上墙。原型里写的是“1 个工作日”。
- 微信服务号模板消息的审核，以及每个用户的推送频次上限。
- 背书和榜单的反作弊：比如互刷背书、批量收录。
- 匿名意向揭晓前，项目方能看到多少信息（原型里只显示身份类型、关注方向和背书数，不显示姓名和机构）。
