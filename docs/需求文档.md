## 1. 背景

### 1.1 现状问题

1. **用户来得少**：创建项目之后，没有让人“下次再回来”的理由。没有数据反馈，动态没人看，也没有周期性的节点。
2. **创建门槛高**：项目档案是一次性填完的长表单，像在“投递 BP”，而不是在“经营一个主页”。
3. **展示弱**：项目页只有静态信息，看不出谁在关注、谁背书、最近在做什么。
4. **合作流程断**：查看联系方式、发起连接、心愿单是三套互不相通的入口。发出之后没有状态，也没有站内对话承接。

### 1.2 方向

把项目从“投递档案”重做为：**创始人公开主页 + 统一意向 + 站内对话 + 背书与路演节律**。参考 Peerlist（主页即作品集、开放状态、榜单）、Contra（直接连接、统一询价入口）、Cosign（署名背书、按维度计数、只做正向）。

### 1.3 核心循环

```
快速创建 → 公开项目页 → 被发现（发现页 / 需求 / 榜单 / 路演 / 活动 / 报道）
  → 关注 · 背书 · 建议 · 意向 → 站内对话 → 申请 Pitch 撮合（商机）
  → 工作台数据与周报 → 发布动态 → 再次被发现
```

每个功能都要回答一个问题：它让循环里的哪一步更顺，或者给了哪个身份一个回来的理由。

## 2. 目标与衡量

### 2.1 产品目标

| 目标 | 对应问题 | 主要手段 |
| --- | --- | --- |
| 让项目 1 分钟上线 | 创建门槛高 | 三项必填快速创建、BP 预填、先发后审 |
| 让项目页“活”起来 | 展示弱 | 动态、背书、建议、徽章、回复速度、熟人信号 |
| 让合作有头有尾 | 合作流程断 | 统一意向、站内对话、撮合 |
| 让每个身份每周都有理由回来 | 用户来得少 | 工作台数据、观察清单、周报、月度路演、榜单、答疑、贡献奖励 |

### 2.2 衡量指标

目标值需要上线前和业务一起定，本文只定义口径。

**北极星指标**：每周进入“对话”的意向数，即被接受的意向数。它同时反映了项目有没有被看到、意向有没有被回应。

| 环节 | 指标 | 口径 |
| --- | --- | --- |
| 创建 | 创建完成率 | 打开创建弹层 → 生成公开页 |
| 创建 | 资料达标率 | 创建 7 天内完成度 ≥ 80% 的项目占比 |
| 曝光 | 项目周浏览、转发占比 | 工作台口径，按 `?from=` 区分来源 |
| 意向 | 意向回应率、48 小时回应率 | 已处理（接受或暂不考虑）/ 收到 |
| 意向 | 回复中位时长 | 近 30 天，与项目页“回复速度”标签同口径 |
| 对话 | 意向 → 对话转化率 | 被接受 / 发出 |
| 撮合 | 撮合申请数、接手时长、成交数 | 运营看板口径 |
| 回访 | 项目方周活跃率 | 一周内打开工作台或发布动态的项目方占比 |
| 回访 | 周报点击率 | 周报内任一条目被点击 / 送达 |
| 社区 | 每月动态、背书、建议、投票数 | 也是贡献任务的完成量 |

### 2.3 本期不做

- 身份认证。身份由用户自选，用“被 N 位投资人背书”作为软认证。
- 负面评价。背书只做正向，没有踩和差评。
- 站内凭空私信。对话只能由“接受意向”产生。
- 付费购买徽章或曝光。徽章只能由真实行为获得。

## 3. 用户与权限

### 3.1 身份

身份由用户在引导里自选，之后可以在主页修改。

| 身份 | 典型诉求 | 来 Pitch 的理由 |
| --- | --- | --- |
| 创始人 | 融资、找渠道、招人、被看见 | 工作台数据、意向、周报、路演 |
| 投资人 | 发现项目、持续跟踪、建立信任 | 观察清单、偏好推荐、答疑、榜单 |
| 人才 | 找合伙或工作机会 | 在招岗位、“正在寻找”、活动 |
| 产业合作方 | 找可服务的项目、展示资源 | “能提供”清单、合作需求、答疑、榜单 |
| Pitch 运营 | 撮合、审核、策展 | 运营看板 |
| 游客 | 先看看 | 可以浏览全部公开内容 |

**会员**：意向次数不限。会员体系的档位和价格不在本期范围，见第 9 节的待定事项。

### 3.2 平台权限

| 能力 | 游客 | 创始人 | 投资人 | 人才 | 合作方 | 运营 |
| --- | --- | --- | --- | --- | --- | --- |
| 浏览项目、人、活动、路演、榜单、信息流 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 关注、发意向、写背书、写建议、投票 | 登录后 | ✓ | ✓ | ✓ | ✓ | 建议不开放* |
| 创建项目 | 登录后 | ✓ | ✓ | ✓ | ✓ | 建议不开放* |
| 观察清单 | — | — | ✓ | — | — | — |
| 建榜单 | — | — | ✓ | — | ✓ | ✓ |
| 开放答疑时段 | — | — | ✓ | — | ✓ | — |
| 预约答疑 | 登录后 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 运营看板、设运营精选 | — | — | — | — | — | ✓ |

\* 运营是工作账号。原型没有限制这两行操作，建议正式版不开放，避免运营的行为影响关注数、背书、票数这些社区信号。

补充约束：
- 不能给自己或自己的项目写背书、投票、发意向。
- 运营不出现在人物列表、在场名单和人物榜里，不能被写背书，也不能被邀请为项目成员。
- 游客点任何需要身份的操作，都弹出登录，并说明登录后能做什么。

### 3.3 项目成员权限

| 能力 | 创建者 | 管理员 | 编辑 | 成员 |
| --- | --- | --- | --- | --- |
| 在主页展示为项目成员 | ✓ | ✓ | ✓ | ✓ |
| 编辑资料、发动态、处理建议、分享物料 | ✓ | ✓ | ✓ | — |
| 处理意向、管理成员、申请上墙和路演 | ✓ | ✓ | — | — |
| 调整成员权限、设管理员 | ✓ | — | — | — |

## 4. 全局规则

以下规则跨多个模块，各模块不再重复。

| 编号 | 规则 |
| --- | --- |
| G1 | **先发后审**：创建即生成公开页 `/p/[slug]`，任何人拿到链接都能看。只有上发现页、进榜单、进月度路演时才看审核状态。审核不影响公开页。 |
| G2 | **可见范围**：“公开到发现”或“仅持链接可见”。仅持链接的项目不进发现页，申请上墙时自动改为公开。 |
| G3 | **完成度**：9 项（名称一句话与赛道、Logo 与封面、介绍 ≥ 30 字、在卖什么、凭什么、正在寻找、≥ 2 位确认成员、联系方式、第一条动态）。达到 80% 才能申请上墙和报名路演。 |
| G4 | **意向次数**：非会员每月 5 次，每类贡献任务每月第一次完成 +1（共 5 类，最多 +5），每月 1 日重置、不累计。会员不限。回复意向、浏览、关注都不消耗；撤回不返还。 |
| G5 | **不泄露拒绝**：发起方在 7 天内看到的都是“等待回应”，7 天后一律显示“暂未回应”，看不出对方是没看还是选了“暂不考虑”。 |
| G6 | **联系方式永不公开**：只在对话里由本人主动分享给对方。 |
| G7 | **隐私**：观察清单和私人备注只有投资人自己可见，项目方只看到人数；路演报名信息只有项目方和运营可见；运营在撮合前看不到对话内容。 |
| G8 | **署名与正向**：背书署名、按维度计数、只做正向。 |
| G9 | **来源归因**：项目页链接带 `?from=`（wechat / moments / poster / discover / demoday / article），没有则记直接访问。成员自己访问不计数。 |
| G10 | **状态规范**：每个列表和模块都要有加载（骨架屏）、空状态（一句原因 + 一句下一步 + 最多两个按钮，不写“暂无数据”）、错误（就地提示）、禁用（说明为什么）。 |
| G11 | **深链**：标签、筛选、弹层都同步到地址（如 `?tab=`、`?create=1`、`?edit=status`、`#feedback`），通知、周报、首页的入口都直接打开对应位置。 |
| G12 | **响应式**：桌面以 1440 为准，移动端以 390 为准，任何页面都不能横向溢出。1280 以下的三栏布局把右栏收进抽屉。移动端有底部 5 栏导航。 |

### M01 首次引导与首页（P0）

**目标**：新用户 1 分钟内知道自己能在这里做什么，并完成第一个动作。老用户打开首页就能看到需要自己处理的事。

**用户故事**
- 作为新用户，我想先说清楚我是谁、在找什么，这样推荐给我的内容是对的。
- 作为任何身份，我打开首页就能看到等我回应的事，不用到处找。

**需求**
1. 引导四步：选身份 → 基本信息（名字、职位必填）→ 开放状态（按身份采集不同字段）→ 3 个第一步。可以“稍后再说”跳出。没完成引导时，首页顶部常驻提示。
2. 填写开放状态即完成“刷新开放状态”贡献任务（意向次数 +1）。
3. 每个身份 3 个第一步，完成状态由真实数据推导，全部完成后卡片消失：

| 身份 | 第一步 |
| --- | --- |
| 创始人 | 创建项目 / 写下正在寻找 / 转发项目页给 3 个朋友 |
| 投资人 | 设置投资偏好 / 收藏 3 个项目到观察清单 / 开放一个答疑时段 |
| 人才 | 设置开放状态 / 关注 3 个项目 / 向在招项目表达意向 |
| 合作方 | 写下能提供的资源 / 回应一条合作需求 / 关注 3 个项目 |

4. 首页按身份不同：
   - 所有登录用户：问候、本月剩余意向次数，以及待处理条（待回应意向、未读对话、成员邀请、待确认答疑），没有待处理时不显示。
   - 创始人：我的项目（7 天浏览与环比、关注、待回应意向、完成度与下一项）、可能帮得上的人。
   - 投资人：观察清单的更新、符合偏好的项目。
   - 人才：在招岗位。
   - 合作方：等你回应的合作需求。
   - 运营：撮合申请、上墙审核、路演报名三个待办数。
   - 游客：落地页。
5. 右栏“正在发生”：直播中的活动、本月路演、下一场活动，以及 Pitch 报道。

**验收标准**
- [ ] 新用户选“创始人”后，首页出现创始人的 3 个第一步；创建项目后第 1 项自动打勾。
- [ ] 新用户填完开放状态后，首页显示“还可发 6 次”。
- [ ] 待处理条的数字和收件箱、我的意向、答疑页的数字一致。
- [ ] 游客看到落地页，点任何动作弹出登录。

### M02 发现页（P0）

**目标**：让对的人找到对的项目和人，并且一步就能表达意向。

**需求**
1. 四个标签：项目 / 人 / 需求 / 榜单。标签和主要筛选同步到地址。
2. **项目**：只显示公开且已上墙的项目（G1、G2）。
   - 筛选：搜索、正在寻找（融资 / 合作 / 招人）、赛道、地区。
   - 排序：熟人关注优先（默认）/ 最近有动态 / 关注最多 / 最新创建。
   - 本人有未上墙的项目时，顶部提示当前状态（未申请 / 审核中 / 未通过及原因），并给出入口。
3. **人**：按身份筛选，可以“只看开放中”。认识的人排在前面。不显示运营和没完成引导的用户。
4. **需求**：汇总项目的“正在寻找”和个人的“正在寻找”，后者即原心愿墙，标“来自心愿墙”。
   - 每条需求直接给出对应动作（我想投资 / 我能合作 / 我想加入 / 我能帮上忙），打开意向弹层并预选类型。
5. **榜单**：运营精选在前。
6. **熟人信号**：“你认识的人”指和你有过对话的人，加上你关注的人。卡片底部显示“某某、某某 你认识的人关注或背书过”。

**验收标准**
- [ ] 审核中、仅持链接的项目不出现在游客的项目列表里。
- [ ] 从首页点“在招岗位”能直达 `?tab=needs&kind=join`。
- [ ] 筛选无结果时出现“清空筛选”。

### M03 项目公开页（P0）

**目标**：项目的“经营主页”。访客一眼看到项目在做什么、在找什么、谁在关注，并且能直接行动。

**需求**
1. 分区（自上而下）：
   - 成员横条：完成度、上墙状态、编辑、工作台，仅成员可见。
   - 封面图集。
   - 头部：Logo、名称、徽章、一句话、标签、地区、官网、关注数、熟人信号。
   - 正在寻找、关于项目（在做什么 / 在卖什么 / 凭什么）、团队、在招岗位、动态时间线、背书、建议区、Pitch 报道、参与的活动。
   - 右栏：意向卡、数据小计、被收录的榜单、相似项目。
2. **意向卡状态**：

   | 状态 | 显示 |
   | --- | --- |
   | 游客 | 点击弹出登录 |
   | 项目成员 | 待回应意向数和回复速度 |
   | 已发、等待中 | “等待回应” + 撤回 |
   | 已接受 | “打开对话” |
   | 7 天未回应（含被暂不考虑） | “暂未得到回应”，可以再试 |
   | 默认 | 四个类型按钮，项目正在寻找的类型高亮 |

3. **回复速度标签**：近 30 天意向回复的中位时长。
   - ≤ 12 小时：“通常半天内回复”
   - ≤ 24 小时：“通常 1 天内回复”
   - ≤ 48 小时：“通常 2 天内回复”
   - 更慢：“回复较慢”
   - 没有记录：“暂无回复记录”
4. **建议区**：分类 + 至少 10 字。默认只有项目方可见；写建议的人能看到自己那条，并标“仅你和项目方可见”。项目方可以公开、标记有用、回复。
5. **背书**：按维度汇总，点开看署名原文。成员不能给自己的项目背书。可以撤回自己写的背书。
6. 投资人访问时，如果项目在 TA 的观察清单里，自动标为已查看。
7. **移动端**：意向卡改为底部固定条（关注 + 表达意向）。

**验收标准**
- [ ] 带 `?from=moments` 访问后，工作台“朋友圈”来源 +1；成员自己访问不计数。
- [ ] 已发意向的访客再次打开，意向卡显示“等待回应”和撤回。
- [ ] 建议对其他访客不可见，直到项目方公开。

### M04 统一意向（P0）

**目标**：用一个入口替代“查看联系方式 / 发起连接 / 心愿墙留言”，并且让发出的每一条都有状态。

**用户故事**
- 作为投资人，我想先匿名表达兴趣，对方也想聊时再揭晓身份。
- 作为项目方，我想集中处理所有意向，不想因为拒绝而得罪人。
- 作为发起方，我想知道我的意向现在到哪一步了。

**需求**
1. **入口**：项目页意向卡、正在寻找的每条需求、在招岗位、发现页需求、首页推荐、个人主页（直接找人），以及活动、报道、路演、榜单的卡片。入口会带上预选类型、需求或岗位，以及来源说明（如“在 Pitch 榜单「某某」看到你，”）。
2. **类型**：想投资 / 想合作（渠道、流量、品牌、服务）/ 想加入团队（可以选具体岗位）/ 帮忙（回应需求时自动带上）/ 其他。
3. **来意**：10–200 字，必填。按类型给 2 条模板。
4. **匿名**：开关旁实时预览“对方会看到什么”。匿名时只显示身份类型、关注方向和背书数，不显示姓名、机构、头像。
5. **发送限制**：
   - 按 G4 计次数。次数用完时，弹层顶部提示并引导去做任务，发送按钮禁用。
   - 同一项目 7 天内只能有一条等待中的意向。直接找人时，同一人同样限制。
6. **项目方处理**：
   - 实名意向：“开始聊” / “暂不考虑”。
   - 匿名意向：“我也想聊” / “暂不考虑”。点“我也想聊”后，双方身份同时揭晓。
   - 接受后自动创建对话：第一条是来意，第二条是系统消息，然后跳转到对话。
7. **发起方视角**：按 G5 显示状态。可以撤回，撤回后对方不再看到，次数不退。
8. **我的意向页**：我发出的 / 我收到的 / 成员邀请，右上角显示本月次数卡。

**验收标准**
- [ ] 匿名意向被接受前，项目方看不到发起人的姓名和机构；接受后双方都看到真实身份。
- [ ] 被“暂不考虑”的意向，发起方 7 天内看到“等待回应”，7 天后看到“暂未回应”，看不出被拒。
- [ ] 非会员用完次数后不能发送，完成一项贡献任务后可以再发。
- [ ] 同一项目 7 天内第二次发意向被拦截，并提示原因。

### M05 收件箱与对话（P0）

**目标**：意向之后的沟通留在站内，并且有一个明确的“请 Pitch 帮忙”出口。

**需求**
1. 对话只由接受意向产生。第一屏固定显示“对话起点”：谁、什么意向、原始来意、关联项目、时间。
2. 消息：文字和附件（BP、产品手册等）。第一次发言前给 3 条快捷开场白。
3. **联系方式**：默认双方互不可见。任一方点“分享我的联系方式”（微信 / 手机 / 邮箱，至少一项）后，对方立即可见。双方都分享后显示“已互换”。
4. **申请撮合**：
   - 任一方都可以申请。选择希望 Pitch 帮什么（线下会面 / 引荐跟投人 / 尽调资料 / 条款建议 / 渠道对接，可多选），并写说明（≥ 10 字）。
   - 每段对话只能申请一次。
   - 撮合是唯一生成 CRM 商机的地方。
5. **对话状态**：进行中 / 已申请撮合 / Pitch 跟进中（结案后显示“撮合成交”或“撮合未成交”）/ 已结束。
   - 结束时选择原因，对方能看到。
   - 可以重新开启，恢复到结束前的状态。
6. **撮合进度**：显示在对话顶部横条和右栏，包括申请、接手、已约见、结果。运营的每次更新都会在对话里留一条系统消息。
7. **未读**：最后一条消息不是自己发的，并且晚于自己的已读时间，就算未读。顶栏收件箱角标 = 未读对话数 + 待回应意向数。
8. **权限**：非成员访问时显示“对话不存在或你无权查看”。运营只能只读查看有撮合的对话。

**验收标准**
- [ ] 一方分享联系方式后，另一方无需刷新即可看到。
- [ ] 申请撮合后，对方和运营都收到通知，运营看板“待接手”出现这一条。
- [ ] 运营打开一段没有撮合的对话时被拦截。

### M06 快速创建与完善（P0）

**目标**：1 分钟生成公开页，之后再慢慢完善。

**需求**
1. 创建只要三项：名称（≤ 20 字）、一句话（≤ 40 字）、赛道，加上可见范围。提交后立即生成公开页，跳到编辑页，并提示“公开页已生成”和复制链接。
2. **BP 预填**：
   - 上传 PDF / PPT / Keynote（≤ 30MB），读取后列出提取到的字段，自动填入表单，用户仍可修改。
   - BP 文件本身不公开、不保存。
   - 在编辑页再传一次时，只填当前为空的字段，不覆盖已写的内容。
3. **编辑页**：
   - 左侧是分区表单，右侧是完成度清单和实时预览（公开页头部 / 发现页卡片）。
   - 有未保存的修改时，离开前要确认。
   - 只有创建者、管理员和编辑能进入（见 3.3），普通成员和其他人会看到说明。
4. **上限**：正在寻找最多 5 条，图集最多 6 张（第一张为封面）。
5. **入口**：顶栏“创建项目”、移动端底栏“+”、首页、引导第 1 步、任务中心。

**验收标准**
- [ ] 只填三项就能生成可访问的公开页。
- [ ] 上传错误格式或超过 30MB 时，上传区就地报错，可以直接重传。
- [ ] 保存后，公开页和完成度立即更新。

### M07 项目工作台（P0）

**目标**：给创始人一个“经营”的地方，用数据告诉他下一步做什么。

**需求**
1. 权限见 3.3。没有权限的分区带锁，并说明原因。
2. **概览**：
   - 四个指标：7 天浏览（含环比）、关注、意向（含待回应数）、对话（含撮合数）。
   - 14 天浏览趋势。
   - 转化漏斗：浏览 → 关注 → 意向 → 对话 → 撮合。
   - 7 个渠道的来源，以及转发占比。
   - “现在最值得做的事”：最多 5 条，按优先级排列。
   - 观察清单只显示投资人人数，不显示是谁。
3. **意向**：复用 M04 的处理组件，只看本项目的意向。
4. **成员**：
   - 搜索站内用户邀请，填写职位并选择权限。对方确认后才进入团队，项目同时出现在 TA 的主页上。
   - 不在站内的人，可以复制邀请链接。
   - 待确认的邀请可以撤回，已确认的成员可以移出。
5. **动态**：6 个模板（上线 / 完成融资 / 招人 / 获奖入选 / 数据里程碑 / 自由发布）。发布后通知关注者和观察清单里的投资人（按 M09 的提醒设置），并计入贡献任务。
6. **建议**：待处理 / 全部 / 已公开。可以标记有用、回复、公开。首次标记有用和首次回复会通知建议人。
7. **曝光**：
   - 申请上发现页：状态有可申请、审核中、已上墙、未通过（附原因，可以重新申请）。
   - 报名月度路演：写“想讲什么”，10–60 字。
   - 被收录的榜单、项目徽章。
8. **分享物料**：按渠道生成带 `?from=` 的链接、按“正在寻找”生成转发文案、项目海报。

**验收标准**
- [ ] 编辑权限的成员打开“意向”时看到锁和说明。
- [ ] 完成度 < 80% 时申请按钮禁用，并给出“去完善”。
- [ ] 发布动态后，关注者和观察者收到通知，自己项目的成员不收到。

### M08 个人主页（P1）

**目标**：人是合作的起点。主页要说清“我是谁、在找什么、能提供什么、谁为我背书”。

**需求**
1. **开放状态**，按身份不同：
   - 投资人：关注赛道 / 阶段 / 单笔金额 / 地区。
   - 人才：开放机会 / 擅长方向 / 到岗时间。
   - 合作方：“能提供”清单，最多 4 项，每项都有“我想要这个”。
   - 创始人：只写一句话，需求写在项目里。
   - 超过 30 天没更新时，访客看到标灰和“可能已过期”，本人看到“刷新开放状态”。
2. **正在寻找（个人）**：原心愿墙的“找人脉 / 求工具 / 求经验”并入这里，最多 3 条，同步到发现页需求。
3. **我在做的事**：沿用名片上的一句话、项目信息、亮点。
4. **关联项目**：只显示已确认的成员身份。
5. **背书**：与项目页同一套。被投资人背书时显示认证标，以及“被 X 位投资人背书”。
6. **直接找人**：按对方身份默认选意向类型（人才 → 邀请加入；合作方 → 想合作）。
7. **其他**：答疑时段卡、徽章、被收录的榜单、TA 整理的榜单。联系方式永不公开（G6）。

**验收标准**
- [ ] 在合作方的“能提供”上点“我想要这个”，意向自动带上这一项。
- [ ] 开放状态更新时间超过 30 天，访客看到“可能已过期”。
- [ ] 个人需求出现在发现页“需求”里，标“来自心愿墙”。

### M09 投资人观察清单（P1）

**目标**：给投资人一个私密的跟踪工具，让项目的每次进展都能送达对的人。

**需求**
1. 只对投资人开放。其他身份打开时说明“这是投资人工具”，引导改用关注。
2. **与关注的区别**：关注是公开计数；观察清单完全私密（G7）。
3. **私人备注**：每个项目一条，≤ 200 字。移出清单时如果有备注，要二次确认。
4. **更新提醒**，按项目设置：
   - 所有动态（默认）。
   - 仅关键动态：上线 / 融资 / 获奖 / 里程碑。
   - 不提醒。
   - 既关注又观察同一个项目时，只按观察清单的设置提醒一次。
5. **“有新动态”**：指上次查看之后发布的动态。首页、周报、清单使用同一口径。
6. **接触状态**：没发过意向 → 等待回应 / 暂未回应 → 对话中。

**验收标准**
- [ ] 项目方只能看到“X 位投资人把你加入了观察清单”，看不到是谁，也看不到备注。
- [ ] 设为“仅关键动态”后，自由发布不提醒，里程碑提醒。
- [ ] 打开项目页后，该项目的“有新动态”消失。

### M10 活动（P1）

**目标**：把线下和线上的“相遇”变成可跟进的连接。

**需求**
1. **两类活动**：
   - 线上直播：不限名额，可以预约提醒。
   - 线下聚会：有名额，满额后不能报名。
   - 月度路演也是一场线上活动。
2. **状态**：报名中 / 进行中 / 已结束。主按钮随状态变化：报名 → 签到或进入直播 → 跟进或看回顾。
3. **现在在场**：签到或进入直播后才能看到完整名单，之前只能看到模糊的预览和人数。名单分人和项目两个标签。
   - 对人“打招呼”：发出直接意向，说明自动带上活动来源。
   - 对项目：发意向。
4. **活动后跟进**：只给在场过的人。可以“全部关注”在场的项目，并提示 48 小时内跟进效果最好。
5. **回顾**：摘要、回放、关联报道、战报入口。

**验收标准**
- [ ] 未签到时看不到在场的人是谁。
- [ ] 打过招呼的人显示“已打招呼”，不能重复发。
- [ ] 线下活动满额后，按钮禁用。

### M11 信息流（P1）

**目标**：项目动态有人看，报道和快讯带来新的发现。

**需求**
1. 三种内容按时间倒序混排：项目动态（只来自公开项目）、Pitch 报道、行业快讯。
2. **标签**：推荐 / 关注（需要登录；包括关注和观察的项目）/ Pitch 报道 / 行业快讯（可以按标签筛选）。
3. 和自己有关的快讯会特别标出：“和你的项目相关”或“和你关注的项目相关”。
4. **鼓励**：对动态的轻量反馈，不发通知。不能给自己的项目鼓励。
5. **转化**：动态卡片上可以关注、表达意向（招人动态默认选“想加入”）。自己的项目标“你的项目”，不显示这两个按钮。
6. **报道阅读**：右侧抽屉，地址带 `?article=`。文中的项目可以关注、发意向，说明自动带上报道来源。

**验收标准**
- [ ] 游客切到“关注”时弹出登录。
- [ ] 通过 `?article=` 打开的链接，直接打开对应报道。

### M12 通知与周报（P1）

**目标**：需要回应的事及时送达，其余的汇总到周报，不打扰。

**需求**
1. **三个出口**：
   - 站内通知中心：完整记录。
   - 服务号即时提醒：只推用户勾选的类型。默认推送意向、对话、成员邀请、答疑预约。
   - 周报（服务号和邮件）：每周一 09:00 发送。
2. 通知是否推送，在产生的那一刻按当时的设置决定，并记录在通知上。之后改设置不影响已有通知。
3. **周报频率**：每周（默认）/ 有待办时才发 / 不接收。
4. **三个版本**，按身份和数据自动选择：
   - 创始人版：数据、待回应、值得做的事、关注你赛道的投资人。
   - 投资人版：观察清单的新动态、符合偏好的项目、答疑、路演、精选榜单。
   - 精选版：其他身份。
5. 周报里的每一条都能直接点进对应页面（G11）。
6. **邮件**：需要填写邮箱，可以单独关闭，可以一键退订，退订只影响邮件。
7. 支持“发一份测试”。

通知类型见附录 A。

**验收标准**
- [ ] 关掉“意向”的即时推送后，新意向只进通知中心，不推送服务号。
- [ ] 周报里的数字与工作台、观察清单的口径一致。
- [ ] 点通知后标为已读，并跳到对应位置。

### M13 月度路演（P2）

**目标**：给社区一个每月的节律。项目有冲刺目标，投资人有固定的看项目时间。

**需求**
1. 每月一期，是一场线上活动，有主题。
2. **报名**：
   - 条件：完成度 ≥ 80% 且公开，不要求已上墙。
   - 在工作台填写“想讲什么”。
   - 每期只能报一次，截止后不再接受。
   - 报名信息只有项目方和运营能看到。
3. **入围**：运营随报随审，每期约 6 个。入围后获得“路演入围”徽章。未入围也会收到通知。
4. **投票**：
   - 与报名并行。每人每期 3 票，同一项目只能投 1 票。
   - 路演夜结束前可以撤回改投。
   - 不能投自己的项目。
5. **随机排序期**：开放后的前几天，名单对每个人随机排序（同一个人当天顺序不变），不公布票数。之后按票数排序并公开。
6. **路演夜**：每个项目 6 分钟展示 + 4 分钟问答。前三名获得“月度路演前三”徽章。
7. **战报**：观看人数、意向数、撮合数、总票数、领奖台、完整排名、回顾。可以分享。

**验收标准**
- [ ] 随机期内，不同的人看到不同的顺序，并且看不到票数。
- [ ] 投满 3 票后，其他卡片的按钮显示“票已用完”，撤回一票后恢复。
- [ ] 自己项目的卡片显示“不能投自己”和“分享拉票”。

### M14 榜单（P2）

**目标**：用可信的人整理的清单做发现，并给被收录者一个可分享的认可。

**需求**
1. **谁能建榜**：运营、投资人、合作方。创始人和人才不能建，避免自荐。
2. **谁能管理**：整理者本人，或运营。只有运营能设为“运营精选”。
3. **两类榜单**：
   - 项目榜：只收公开且已上墙的项目。
   - 人物榜：只收已选身份的成员，不含运营。
4. **上限**：每条必须写收录理由（1–40 字）。每个榜单最多 20 条。榜单名 ≤ 30 字，说明 ≤ 80 字。
5. **通知**：
   - 项目被收录，通知负责人和管理员；人被收录，通知本人。
   - 关注榜单的人收到“新增了某某”。
   - 移除不通知。
6. **运营精选**：在榜单页置顶、在发现页排最前，并进入周报。
7. 详情页说明：榜单是整理者的个人判断，不代表 Pitch 背书。

**验收标准**
- [ ] 创始人看不到“新建榜单”。
- [ ] 没写收录理由时不能收录。
- [ ] 项目页和个人主页显示“被收录的榜单”，包括名次和理由。

### M15 贡献奖励与徽章（P2）

**目标**：奖励对社区有价值的行为，并且和意向次数打通。

**需求**
1. **5 类贡献任务**，每类每月第一次完成 +1 意向次数（G4）：
   - 写建议（≥ 10 字）
   - 写背书
   - 路演投票
   - 发项目动态（只有管理项目的人适用）
   - 刷新开放状态
2. 完成任务时收到通知“贡献任务完成，意向次数 +1”。撤回投票、删除动态都不扣回奖励。
3. **个人徽章**，由真实行为自动获得：
   - 社区贡献者：单月完成至少 4 项。门槛是 4 而不是 5，因为没有项目的人做不了“发动态”。
   - 10 人背书。
   - 100 关注。
   - 早期成员。
4. **项目徽章**：Pitch 报道 / 路演入围 / 月度路演前三 / 回复迅速。在任务中心只做展示。
5. **任务中心**：本月次数、任务进度、每项任务的具体去处（推荐对象）、徽章进度、按月的贡献记录。

**验收标准**
- [ ] 同一类任务在同一个月做两次，只加一次。
- [ ] 单月达到 4 项时收到“获得徽章：社区贡献者”，并在主页显示。
- [ ] 没有项目的用户，“发项目动态”显示“暂不适用”，并可以去创建项目。

### M16 答疑预约（P2）

**目标**：给投资人和合作方一个低成本的“开放时间”，给创始人一个能约到人的正式渠道。

**需求**
1. **谁能开放时段**：投资人、合作方。所有登录用户都可以预约，但不能约自己的时段。
2. **开放时段**：
   - 主题 1–20 字。
   - 时间：未来 14 天内，09:00–21:30 开始。时长 20 / 30 / 45 / 60 分钟。
   - 方式：线上，或线下（在答疑人所在城市）。
   - 不能和自己未结束的时段重叠。同时开放的时段最多 6 个。
3. **预约**：
   - 写说明（10–120 字），不消耗意向次数。
   - 同一位答疑人，同时只能有 1 个未结束的预约。
4. **确认**：必须填会议链接或见面地点，只发给预约人。婉拒时可以写原因，时段重新开放。
5. **取消**：
   - 预约人可以取消，答疑人收到通知，时段重新开放。
   - 答疑人取消已确认的答疑时可以写原因，预约人收到通知。
   - 答疑人删除没人约的时段，不通知任何人。
6. **过期**：开始前没确认的预约、没人约的时段，自动过期。已结束的答疑可以“继续聊聊”，即带着来源发意向。

**验收标准**
- [ ] 新时段与已有时段重叠时，提示和哪个时段重叠。
- [ ] 不填会议信息不能确认。
- [ ] 已约过某位答疑人时，TA 的其他时段显示“已约过 TA”。

### M17 运营撮合看板（P2；撮合部分随 M05 上线）

**目标**：让撮合成为可管理的商机流程，并把审核集中在一个地方。

**需求**
1. 只有运营能打开。
2. **撮合**：
   - 阶段：跟进中 → 已约见 → 成交 / 未成交。成交和未成交表示结案。
   - 接手、主动介入、更新进展时，都必须写说明（≥ 6 字）。说明会同步给双方：对话里加一条系统消息、双方各收到一条通知、顶部横条和右栏进度更新。
   - 每一步都记入跟进记录，包括日期和操作人。
   - 同一段对话只能由一位运营接手。已结束的对话不能主动介入。
   - **主动介入**的对象：还没申请撮合，但出现了投资意向、互换了联系方式，或近 7 天超过 4 条消息的对话。介入前运营看不到对话内容（G7）。
3. **高意向项目**：
   - 按近 14 天的意向数（投资意向加权）、投资人观察数、7 天浏览量排序，显示前 8 个。
   - “提醒回应”：有意向超过 2 天没回应时可用，同一项目一天一次。
   - “收进榜单”：只能用运营自己策展的项目榜，项目必须已上墙。
4. **上墙审核**：
   - 通过后，项目进入发现页。
   - 不通过时必须写原因，可以用预设原因。项目方收到原因后可以重新申请。
5. **路演审核**：
   - 显示入围进度（目标约 6 个），已入围的同赛道项目会提示。
   - 入围后颁发徽章。不入围时原因选填。

**验收标准**
- [ ] 撮合每次更新，双方都收到通知，对话里出现记录。
- [ ] 结案后，对话状态显示“撮合成交”或“撮合未成交”。
- [ ] “可以主动介入”的卡片里看不到消息内容，也没有“查看对话”。
- [ ] 不通过上墙审核时，不写原因就不能提交。

## 7. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 隐私 | 按 G6、G7 执行。匿名意向揭晓前，接口层也不能返回发起人的身份信息，不能只在前端隐藏。 |
| 权限 | 页面和接口都按 3.2、3.3 做校验。无权限时给出说明，不能只是隐藏入口。 |
| 响应式 | 按 G12 执行。移动端的关键动作（意向、保存、投票）放在底部固定条。 |

| 深链 | 按 G11 执行。所有通知和周报链接都要能落到具体位置，带 `#` 锚点的要在数据加载后滚动到位。 |
| 时间 | 统一北京时间。月度重置、周报统计周期、“7 天”“48 小时”等规则都按服务端时间计算。 |

| 视觉 | Untitled UI 风格。品牌色：主色 zinc-900、辅色亮黄 `hsl(60 100% 58%)`、点缀紫 `hsl(259 52% 48%)`。组件见原型 `/ui`。 |

## 8. 原型与正式实现的差异

原型为演示做了以下简化，正式实现时需要补上：

| 原型里 | 正式实现 |
| --- | --- |

| 会员只是一个开关 | 会员体系（见 9） |
